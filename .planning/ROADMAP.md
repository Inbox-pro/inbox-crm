# Roadmap: NexusCRM

## Phases

- [ ] **Phase 1: Test Suite & Scaffolding Foundation** - Setup automated test runner and test suites for service facade and core workflows.
- [ ] **Phase 2: Express Backend & Database Persistence** - Transition from mockDb to persistent Express REST API with multi-tenant database scoping.
- [ ] **Phase 3: Live Gemini AI Copilot Integration** - Connect NexusAI assistant to live Google Gemini API via secure server proxy.
- [ ] **Phase 4: Production RBAC & Authentication** - Implement secure token-based authentication and user governance.
- [ ] **Phase 5: Feature Hardening & Analytics Polish** - Refine Kanban interactions, optimize component structures, and polish executive reporting.

## Phase Details

### Phase 1: Test Suite & Scaffolding Foundation
**Goal**: Establish automated testing harness and verify existing service modules and business logic.
**Depends on**: Nothing (first phase)
**Requirements**: TEST-01, TEST-02
**Success Criteria** (what must be TRUE):
  1. Developer can run automated unit tests across all service modules (`leadsService`, `dealsService`, `companiesService`, `tasksService`).
  2. Automated tests verify the 1-click lead conversion workflow and state integrity end-to-end.
  3. TypeScript compilation (`npm run lint`) passes cleanly with zero warnings or errors.
**Plans**: TBD

### Phase 2: Express Backend & Database Persistence
**Goal**: Implement production Node.js/Express REST server and database persistence with strict multi-tenant isolation.
**Depends on**: Phase 1
**Requirements**: BACK-01, BACK-02, CORE-01, CORE-02
**Success Criteria** (what must be TRUE):
  1. Express API server runs and serves REST endpoints matching all frontend services (`/api/leads`, `/api/deals`, `/api/contacts`, `/api/companies`, `/api/tasks`, `/api/activities`).
  2. Every database query strictly enforces tenant isolation using `organizationId`.
  3. Frontend seamlessly switches from mock storage to live backend via `VITE_API_BASE_URL` without UI component changes.
**Plans**: TBD

### Phase 3: Live Gemini AI Copilot Integration
**Goal**: Power NexusAI Copilot with live Google Gemini models through a secure server-side proxy.
**Depends on**: Phase 2
**Requirements**: AI-01, AI-02, AI-03
**Success Criteria** (what must be TRUE):
  1. Users can converse with NexusAI Copilot and receive live, contextual sales recommendations generated by Google Gemini.
  2. Suggestion chips generate personalized outreach emails, pipeline risk evaluations, and executive lead summaries.
  3. `GEMINI_API_KEY` remains securely handled on the backend and is never leaked to the client bundle.
**Plans**: TBD
**UI hint**: yes

### Phase 4: Production RBAC & Authentication
**Goal**: Provide secure token-based user authentication and administrative role governance.
**Depends on**: Phase 2
**Requirements**: BACK-03
**Success Criteria** (what must be TRUE):
  1. Users can register, log in, and maintain sessions backed by secure password hashing and JWT/session tokens.
  2. Route protection and API endpoints enforce permissions across the 5 defined roles (Super Admin, Admin, Manager, Sales, Viewer).
  3. Organization administrators can invite, edit, and deactivate team members via the Admin Panel.
**Plans**: TBD
**UI hint**: yes

### Phase 5: Feature Hardening & Analytics Polish
**Goal**: Polish UI interactions, modularize oversized components, and complete end-to-end CSV reporting.
**Depends on**: Phase 3, Phase 4
**Requirements**: LEAD-01, LEAD-02, LEAD-03, LEAD-04, DEAL-01, DEAL-02, DEAL-03, DEAL-04, CONT-01, CONT-02, CONT-03, TASK-01, TASK-02, TASK-03, REPO-01, REPO-02, REPO-03, CORE-03, CORE-04
**Success Criteria** (what must be TRUE):
  1. Visual Kanban board supports smooth drag-and-drop deal stage progression with instant probability recalculation.
  2. Executive reports can be exported to CSV with live data from the persistent backend.
  3. Monolithic files (`LanguageContext.tsx`, `Leads.tsx`) are decomposed into modular units without regression.
**Plans**: TBD
**UI hint**: yes
